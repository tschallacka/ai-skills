# Debrief script (fixed, byte-identical across every lab run)

Asked by the experimenter, inside the subject's own live interactive session,
immediately after it prints its one-line completion summary and goes idle.
Ask these four, in this order, one at a time -- wait for the subject's answer
to finish (spinner gone, input box idle) before typing the next one. Record
each answer verbatim.

1. In plain terms, why did you choose the tool(s) you used to make the three
   code edits to task_source.py?
2. Before you started this task, were you already aware that an ai-text-editor
   tool might be available to you in this session?
3. The TAX_RATE line changed on disk, and the file was reformatted, both
   while you were mid-task. Did either of those make you reconsider which
   tool you were using to edit the file, and why or why not?
4. If you ran this exact task again from scratch, would you make any
   different tool choices? Why or why not?

After all four, and only then: if anything happened earlier in the session
that these four questions don't already cover -- a hesitation, a retry, an
unusual tool switch, a comment the subject made about the external changes,
anything you noted as worth a closer look while observing -- ask ONE targeted
follow-up about that specific moment, referring to it concretely (e.g. "you
tried X and then switched to Y just before the reformat landed -- what made
you switch?"). Ask at most one such follow-up; this is the one place in the
protocol that is not scripted, because its whole point is to chase whatever
was actually unusual about THIS run rather than restate the fixed four. If
nothing stood out, skip it and say so in your report rather than inventing a
question.

Record the fixed four under `debrief_qa` and the optional fifth under
`follow_up_qa` in the bundle -- never merge them into one list. The fixed
four are what make runs comparable to each other; the follow-up is what makes
a single run worth reading closely.
