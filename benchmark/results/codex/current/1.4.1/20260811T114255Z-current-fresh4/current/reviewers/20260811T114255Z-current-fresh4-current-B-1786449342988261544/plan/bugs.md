## Bug recovery protocol

No browser story was executed during this planning-only benchmark, so no runtime bug is recorded yet. During future execution, any US-01 failure must add a numbered row before fixes begin. The row must include the failed story, severity, exact click sequence and observed result, investigation goal, fix goal, retest story, and status.

Failures that require a bug row include wrong append count, appending from a non-last button, counting the initial button as generated, completing on the fourth append click instead of the later fourth-generated-button click, failing to clear previous document content, text other than exact lowercase finished, or an invisible/non-white border. The affected work unit or step must be reopened, the fix must be represented in the inventory and progress trackers if it changes scope, and US-01 must be rerun before approval.
