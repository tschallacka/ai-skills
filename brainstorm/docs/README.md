# Brainstorm

**Settle what to build before committing to building it.**

Say "brainstorm" and this skill runs a short, recorded back-and-forth: it asks
the questions that matter, writes the answers down, and stops when the idea is
specified enough to plan — or flags that it never will be.

## What you get

- **A recorded picture, not a vibe.** The exchange lands in `brainstorm.md`:
  objective, agreed scope, rejected alternatives, open questions with owners,
  assumptions, edge cases. Anyone can read why the thing is shaped this way.
- **An adversarial pass before you leave.** The skill attacks its own summary
  for completeness gaps before declaring the idea ready — the cheap round, not
  the expensive one after implementation.
- **A gate, not a gateway drug.** Planning off the back of a brainstorm is a
  deliberate step: the document says whether the idea earned a plan or needs
  another round.

## Quick start

> Brainstorm: I want search over my notes but I keep flip-flopping on scope.

Answer the questions; the skill records and converges. When you're done you
have a document you can hand to the planning skill — or a clear reason to
stop.

## Good to know

Small, fully-specified changes skip this — it exists for ideas that could
branch in materially different directions. Nothing is implemented during a
brainstorm; exploration only.
